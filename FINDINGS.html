385 sessions · 1.22 B tokens · $1,951 · workflow-driven analysis

Ranking = impact × confidence ÷ effort, with cross-specialist deduplication so each recommendation appears once with its strongest support.

Top recommendations (ranked, confidence-scored)

#1

Failed-retry loop breaker with hypothesis-change gate

conf 0.90 impact: high effort: low
Evidence
681 failed-retry loops corpus-wide (~1.77 / session); largest single waste category. Top offender: test pi chrome session (37 retries, $106, 317 tool calls).
Action
Per-(tool, target) failure counter. On 3rd deterministic failure (ENOENT, EPERM, syntax, "not unique") inject a forced-reasoning turn demanding a new hypothesis or escalation. Transient errors keep free backoff retries.
Expected outcome
Eliminate the bulk of those 681 loops; conservatively trim 10–20% off tail-session tool-call counts and proportionally cut the p95+ $/session.
#2

Duplicate-arg replay detector + cached inline + escalation

conf 0.88 impact: high effort: low
Evidence
537 exact-replay calls (tool + args byte-identical), concentrated in long sessions — 89/317 in test pi chrome, 77/414 in the implementation-notes loop. Zero new information for non-zero cost.
Action
Session-scoped LRU keyed by (tool, normalized_args) for idempotent tools (Read, Grep, find_files, ctx_search, ctx_execute_file). 2nd identical call returns cached result with [cached]; 3rd forces a planning turn; 4th escalates to summarize-and-handoff. Bash/network stay non-cacheable.
Expected outcome
Directly trims input-token spend on the long-session tail; visibly shortens sessions that loop on the same Read/Grep.
#3

PreToolUse orchestration gate on session-first multi-file mutations

conf 0.82 impact: high effort: medium
Evidence
workflow calls = 0/385. subagent used in 18% of sessions (AGENTS.md floor: >30%). Cross-corpus subagent / (write+edit+bash) = 0.035 — 10× under the explicit floor. Prose loses to conversational tempo.
Action
Extension hook orchestration-gate: when the first Write/Edit/Bash-mutate of a session touches >1 directory or creates >1 new file AND prior subagent dispatches = 0, block. Return structured remediation naming /parallel-research, /parallel-context-build, or scout-async. Explicit --ack-skip-orchestration <reason> bypass, logged for self-grading.
Expected outcome
Moves subagent adoption from 18% toward the >30% target; cuts parent-context bloat (and downstream $) on the heaviest-cost session class.
#4

Real-tool few-shot examples + batched-tool description leadership

conf 0.80 impact: high effort: low
Evidence
Parallel/serial ratio 0.127 despite explicit directive. Current system-prompt example uses a fictional example_complex_tool — models pattern-match to examples, not abstractions.
Action
(a) Replace the fake-tool example with 2–3 real-tool examples (parallel Read × 3; Grep + find_files + Read; multi-command ctx_batch_execute) annotated "independent → one block." (b) Edit descriptions of ctx_batch_execute, fff_multi_grep, web_search to lead with the batch use-case. (c) Add to ctx_execute: "For ≥2 independent commands, use ctx_batch_execute instead."
Expected outcome
Lift parallel/serial ratio from 0.127 toward 0.25+; cut wall-clock latency on read-heavy turns.
#5

Verify prompt-caching is enabled on the stable system-prompt prefix

conf 0.75 impact: high effort: low
Evidence
The system prompt (skills + AGENTS.md + tool descriptions) is ~30 KB and identical turn-over-turn within a session. 385 sessions × multi-turn × 30 KB ≈ a meaningful share of $1,951 if not cached.
Action
Audit pi's Anthropic client wrapper for cache_control: {type:'ephemeral'} on the stable system-prompt block and the skills/AGENTS.md region. Add a regression test asserting prefix-hash stability across turns. If absent, enable.
Expected outcome
If currently off: ~90% cut on cached-prefix input cost — plausibly 20–40% of total $1,951. If on: confirms and closes the question.
#6

Block interactive-TTY commands at the Bash tool boundary

conf 0.78 impact: high effort: low
Evidence
"sudo: a terminal is required to read the password" loop pattern across Bash's 271 errors (5.6% rate). The failure looks like "no output" rather than "needs TTY", so the model retries.
Action
Pre-flight Bash commands against a deny/needs-TTY list (sudo without -n, interactive ssh, vim, less without piping). Return a structured error naming the cause ("requires TTY; rerun with sudo -n or pipe input") instead of letting the process hang.
Expected outcome
Removes a contributor to both the 681 failed-retries and long-session tail durations.
#7

Fuzzy-fallback Edit.oldText anchoring + stale-cache invalidation

conf 0.82 impact: high effort: medium
Evidence
Edit's 6.3% error rate is dominated by "oldText not unique / not found" — usually whitespace/CRLF drift, or anchoring against a stale Read cache after another tool mutated the file. The Read-retry-after-Edit pattern is the signature of anchor staleness.
Action
Two-tier match: exact first, then whitespace-normalized (CRLF/LF, trailing whitespace, tab/space drift). Accept only if exactly one normalized candidate; otherwise return the candidate list for disambiguation. Hook write tools to bump a per-path version counter that invalidates Read caches.
Expected outcome
Cuts Edit-retry-after-Read churn — contributor to both failed-retries (681) and dup-arg Reads (subset of 537).
#8

Per-session cost + orchestration telemetry ledger (JSONL)

conf 0.90 impact: high effort: medium
Evidence
This analysis ran on aggregate-only data; per-session cost histogram, model/tier distribution, task-class breakdown, per-error-cluster counts, and per-session orchestration ratios are not in the corpus. Every recommendation below 0.85 confidence carries residual uncertainty for this reason.
Action
Cost-and-orchestration hook appending JSONL to ~/.pi/telemetry/{cost,orchestration}.jsonl: {session_id, task_class, tool, model, input_tokens, output_tokens, cached_tokens, cost_usd, ts} plus per-session rollup {write_n, edit_n, bash_mutate_n, subagent_n, async_n, workflow_n, ratio}. Ship pi cost and pi sessions analyze --orchestration CLIs. Local-only, opt-in for upload.
Expected outcome
Converts ≥10 second-tier items from "directional 0.55–0.75" to measured numbers within a week of new data. Indirect impact but the highest-leverage enabler.
#9

Hard tool-call ceiling with forced-summarization at p99 (~260 calls)

conf 0.78 impact: high effort: medium
Evidence
p99 = 258 tool calls; max = 414. The ~60% gap above p99 is the long tail consistent with runaway loops, not legitimately large jobs. Reinforced by failed-retry and dup-arg counts concentrating in the same sessions.
Action
Circuit-breaker at ~260 calls: inject a synthetic system turn forcing summarize-to-disk → declare remaining work as todos → hand off to a fresh-context continuation that inherits the digest. Non-destructive. Exempt sessions whose recent N calls show diverse tool/arg signatures.
Expected outcome
Bounds worst-case session $. Capping the max-414 sessions at ~260 with handoff trims ~150 calls × avg-cost from the worst sessions — disproportionate $ impact on the long-tail.
#10

Flip subagent dispatch default to async: true

conf 0.72 impact: medium effort: low
Evidence
Of subagent-using sessions, only 11/18 ≈ 61% used async. ~40% of delegations block the parent despite AGENTS.md saying "Foreground is the explicit opt-out, not the default." workflow already defaults background: true — precedent exists.
Action
Flip schema default of async in the subagent tool definition. Update the system-prompt guideline that currently says async (default: false). One release of dual-default migration behind a config flag.
Expected outcome
Moves toward AGENTS.md's prescribed posture; reduces parent-session context bloat on the 40% currently blocking. Compounds with #3.

Second tier (ship after telemetry makes them measurable)

Sixteen items in the confidence band 0.55–0.78. They are credible but under-measured against the top tier; #8 (the telemetry ledger) is the lever that converts most of them into ranked, evidence-backed work.

  • Default new workflow agents to medium tier; require opt-in for big. 0.55 Plausible mechanism, no tier-distribution evidence yet — needs telemetry on per-agent model picks before flipping the default.
  • Hard per-session $ budget with graceful tier degradation. 0.60 Long-tail cost shape is inferred from tool-call counts; #8 will calibrate thresholds before this can ship safely.
  • Mandatory ctx_execute / ctx_batch_execute for tool outputs >20 lines. 0.70 Promote context-mode routing from advisory to default-on for new installs; the routing already exists, only the default is conservative.
  • Per-session subagent : Write ratio in the TUI status line. 0.70 In-loop visibility nudge with precedent — todo lists work for the same reason: cheap, persistent, low-friction.
  • Promote named recipes (/parallel-review, /review-loop, etc.) to first-class slash commands or saved workflows. 0.78 Zero workflow calls across 385 sessions says the authoring surface is too expensive on demand; pre-bake the common shapes.
  • Fix the context-mode active-banner to mention subagent precedence. 0.74 One-line change at injection time; per-turn banner beats a per-session doc the model has long forgotten.
  • Auto-upgrade detection + structured "outdated" result for ctx_*. 0.74 An outdated-version warning appears in essentially every ctx_* error in the corpus; surface it as a typed result, not a string.
  • MCP timeout retry-with-backoff at the harness layer. 0.70 Transparent retry plus a circuit breaker instead of bubbling opaque timeouts up to the model, which then triggers the failed-retry loops counted in #1.
  • ask_user_question field-level error locality instead of whole-questionnaire reject. 0.76 22.4% error rate is largely schema-validation churn — pinpoint the offending field, do not invalidate the whole batch.
  • Sliding-window context compactor triggered by call density, not just tokens. 0.70 Token-only thresholds miss the runaway-loop shape, which is many small calls rather than one large blob.
  • Turn-scoped snapshot for goal + standing-orders state (fixes GOAL-STALE in-turn bouncing). 0.78 A consistent in-turn view of goal/standing-orders prevents the bouncing-state class of errors that cluster on goal-managing tools.
  • Per-turn batching detector with a system-reminder feedback channel. 0.62 Detect ≥2 independent serial calls in one turn and emit a single reminder, not an avalanche.
  • Auto-fanout escalation at the p95 tool-call mark. 0.60 Earlier and softer than #9's hard ceiling — nudge to a planner subagent before the circuit breaker has to fire.
  • Chrome-extension liveness probe with degrade to fetch_content + direct API. 0.62 chrome_tab 53% error rate, chrome_evaluate 27% — degrade gracefully rather than letting the agent loop on a dead bridge.
  • Explicit /tempo-mode opt-in with end-of-session "what should have been orchestrated" report. 0.55 Make the conversational-tempo bypass legible and accountable instead of silent and habitual.
  • Planning-prompt convention: emit Parallel set: {tools} before each tool block. 0.58 A textual pre-commit that makes the model's batching intent visible to both the harness and the user — cheap reinforcement of #4.

Why these sit below the top ten: each one is plausible, but its sizing leans on inference rather than measurement. Ship #8 first, let one week of ~/.pi/telemetry/*.jsonl accumulate, then re-rank this list against real per-task-class cost and orchestration-ratio numbers. Expect at least three of these to climb into the top tier — likely the recipe-promotion item, the goal/standing-orders snapshot, and the ctx_batch_execute default — and one or two to fall off entirely.

What I (the user) should do differently

These are usage-side, not harness-side. Until the runtime gates above ship, they are the contract; after the gates ship, they are still the cheap path that avoids the gate firing in the first place.

  1. Use workflow / subagent-async on multi-file work. The corpus shows literally zero workflow calls and only 11% of sessions using async — and I am the user across most of those sessions. The AGENTS.md HARD RULE was added precisely because of this pattern; treat it as a contract until #3 lands as a runtime gate.
  2. Stop saying "go ahead" or "just ship it" to skip orchestration. Standing orders explicitly call out conversational tempo as the bypass that is not supposed to work. Whether or not the harness gates it tomorrow, give the agent an actual mandate to delegate instead of an implicit license to plow through.
  3. Run /ctx-upgrade and /ctx-doctor periodically. Outdated context-mode is a contributor to disk-I/O and MCP-timeout errors; the outdated-version warning was visible in essentially every ctx_* error in the corpus. A two-minute upkeep beats debugging a stale-binary failure inside a paid session.
  4. Stop debugging chrome-extension flakiness inside a coding session. The $106 test pi chrome session is the single most expensive in the corpus — highest dup-arg count, highest failed-retry count, and the loop never converged. When the extension is broken, the right move is to file a fix against the extension, not iterate against it inside an agent loop.
  5. For long investigative sessions, dispatch a planner subagent at ~p90 (≈90 tool calls) rather than waiting for the harness to enforce it. The 414-call implementation-notes session is the only one in the corpus that hit stopReason="length"; a midway re-plan would almost certainly have averted it, and it costs one cheap subagent call to find out.

Meta-notes & artifacts

  • The aggregate JSON has per-session rows, but raw user prompts and tool arguments were deliberately not sampled beyond the first 200 chars (privacy posture). A per-task-class breakdown (feature / refactor / debug / conversation) would let us size recommendations #3, #4, and #9 precisely. Easiest path: cluster the firstUserPrompt field in sessions_summary.json by topic.
  • We do not yet know whether prompt caching is on — recommendation #5 collapses to a no-op if it is.
  • 90 turns ended with stopReason="error" and 30 with aborted; those are worth a separate pass to see if they cluster on specific tools or models.
  • The corpus is 94% claude-opus-4-7. Per-task tiering (Haiku for grep/read fan-out, Sonnet for synthesis, Opus only for judgment) is plausibly the largest single dollar cut available after prompt caching is verified, but lacks direct evidence in this corpus.
