Claude Code source adapter for pi-lookback

main · worktree /Users/anishthite/workspace/pi-lookback · 2026-06-04 · status shipped · blast med

Summary

Goal
Make pi-lookback source-agnostic: ingest both pi sessions (~/.pi/agent/sessions/) and Claude Code sessions (~/.claude/projects/<path-encoded>/*.jsonl) through a pluggable source-adapter layer; unified library view with a source filter.
User decision
Unified library + source filter (single list, sortable by recency across both agents).
Surface
New src/sources/{pi,claude-code,index}.js; src/parser.js becomes a dispatch shim; src/scanner.js, src/summary.js, src/signals.js, src/api.js, server.js, public/app.js get source-awareness; new fixtures for Claude Code; new test pass.
Constraints
Read-only (M9 gate preserved). No new runtime deps. Node ≥18. Existing pi gates must still pass.

D-1 · Architecture decision: extend, not fork

ChoiceSource-adapter layer inside the existing pi-lookback codebase.
Rejected alternativeFork as claude-lookback. Would duplicate scanner/summary/signals/api/export-html/server/UI (~85% of LOC) for no semantic gain; loses cross-agent recency browsing.
RationaleSchemas diverge only at the parser layer. Everything downstream consumes a normalized entry stream. One UI, one search, one signals/metrics harness.
ReversibilityHigh. Adapters are isolated under src/sources/; reverting to pi-only is a one-line registry change.

D-2 · Adapter contract (provisional — final shape after planner)

Each adapter exports{ id, defaultRoot, discover(root), parseFile(path), normalize(rawEntry) }
discover(root)Yields { sessionPath, projectCwd, sessionId }. pi: walks ~/.pi/agent/sessions/. claude-code: walks ~/.claude/projects/, decodes dir name → cwd.
normalizeReturns the existing pi-lookback normalized entry shape: { id, parentId, ts, kind, role?, text?, toolName?, toolArgs?, toolResult?, bash?, usage?, model?, raw }. kind is the rendered category; unknown raw types map to kind: "unknown" with the original payload in raw.
SidechainsClaude Code's isSidechain: true entries set kind: "message" with a sidechain: true flag; renderer adds a subagent badge.
