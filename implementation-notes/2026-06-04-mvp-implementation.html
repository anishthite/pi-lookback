Decisions

IDChoice · Rationale
D-001Pure Node stdlib, zero runtime deps. Plan said "Node + React/Vite". MVP gets faster boot, no install pain, and the metrics gate (search p95 18ms, large session p95 37ms) doesn't need a framework.
D-002Vanilla JS frontend instead of React. Same reasoning as D-001. Three views are simple enough that a 500-line app.js is more readable than a build chain.
D-003Branch detection from parentId tree (children-per-parent count). The corpus has 0 branch_summary entries — relying only on that type would mis-report all branches as zero.
D-004mtime-keyed summary cache. Re-parsing 352 files on every /api/sessions hit would blow the <2s gate immediately. Cache keyed on (mtime, size) so external changes invalidate automatically.
D-005Detail payload truncates very large text/output to 4 KB and flags textTruncated/outputTruncated. Keeps 700+ entry sessions snappy in the UI; raw bytes available via /api/sessions/:id/entry/:entryId.
D-006Review-worthy score is a linear weighted sum: failed_tool×4 + failed_bash×6 + branches×5 + compactions×3 + min(cost×100, 40) + parseErrors×10 + (entryCount>500 ? 5 : 0). Bash failures weigh more than tool errors because they imply repeat-without-progress.
D-007Read-only enforced by never opening session files with write flags and by gate M9 (mtime invariant on 50 files across a representative browse pattern).
D-008Heuristic correction-phrase regex over {no(t)?, wrong, you forgot, actually, fix(ed)?, i said, that('s|is) (not|wrong), incorrect, stop, don't, undo}. False-positive-tolerant by design — signal is for ranking, not labeling.

Deviations

IDFrom spec · Did · Reason
X-001Plan said React/Vite. Shipped vanilla JS. Rationale in D-002; behavior parity preserved.
X-002Plan mentioned branch_summary entries explicitly. None exist in current pi v3 corpus; branch detection falls back to parentId tree. Reversibility: when pi adds branch_summary entries, the parser already normalizes them; UI shows them as a separate kind.

Tradeoffs

IDPicked over Rejected · Reason
T-001Lazy per-file parse with cache over upfront corpus index. Index would speed full-text search further, but adds disk-state to manage and isn't needed to pass the <300ms p95 gate.
T-002Linear trace render (one big list) over virtualized list. Largest session has 844 entries; renders comfortably without virtualization. If sessions ever pass ~5k entries this should be revisited.
T-003One HTTP process serves API + statics over separate processes. Simpler ops, no CORS, easier to ship a single-binary later (e.g. pkg).

Assumptions

  • A-001 · Sessions stay in pi v3 JSONL shape captured in docs/session-examples.json. If shape changes, parser falls back to kind: 'unknown' — verified by fixture unknown-entry.jsonl.
  • A-002 · Single-user local desktop usage. No auth, no multi-tenant, no remote sessions root.
  • A-003 · Cost figures from usage.cost.total are USD. Used in high_cost signal (>$1.00) and library badges.

Reversibility

R-001 · low. Delete pi-lookback/; no files outside the workspace are touched and no global state is added.
