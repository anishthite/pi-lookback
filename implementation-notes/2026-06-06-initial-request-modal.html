Initial-request modal — view pi's reconstructed system prompt

Task. User asked: "is there any way we can see the system prompt or like the full initial message that is sent? im curious why its so big. add a view to pi lookup where if i click on the message i can see this".

Decisions

iddecisionwhy
D-1Reconstruct the system prompt rather than try to extract it from the session.pi does NOT persist the rendered system prompt in JSONL. dist/core/system-prompt.js builds it in-memory from cwd + AGENTS.md + skills at request time. The session only stores user text, assistant usage, and a stats_initial_prompt_estimate custom event.
D-2New module src/initial-input.js; new route GET /api/sessions/:id/initial-input.Keep the reconstruction logic out of summary.js / signals.js; it's an on-demand read, not part of every list call.
D-3Trigger via (a) toolbar button "Initial request" and (b) clicking a user message in the trace pane.User said "if i click on the message i can see this". Toolbar button is a discoverability backup.
D-4For non-first user messages, the modal shows only the full untruncated text. The composition view is first-user-only.Subsequent user turns don't trigger a fresh system-prompt build; only the first does. Showing composition on every turn would be misleading.
D-5Show three sources of truth: (1) pi's logged stats_initial_prompt_estimate, (2) first assistant usage.cacheWrite, (3) reconstructed file list with current contents.(1)+(2) are exact and from the session. (3) is approximate (files may have changed). The UI surfaces this caveat in a yellow note.

Tradeoffs

idtradeoff
T-1Reading current AGENTS.md/SKILL.md from disk means the displayed content can drift from what pi actually sent at session time. Accepted as v1 because (a) the user is reviewing their OWN past sessions on their OWN machine, so disk state is usually close, and (b) the alternative (storing the rendered prompt in JSONL) requires a pi PR. Caveat surfaced in UI.
T-2Skill discovery walks ~/.pi/agent/skills, ~/.agents/skills, npm-installed extension skills (pi-subagents, context-mode, pi-web-access, pi-autoresearch), and $cwd/.pi/skills. We cap at 60 skills total. Some installations might surface skills from other paths; we'll add those if a session shows obvious gaps.
T-3Per-file preview capped at 32 KB and total embedded content capped at 512 KB so a session with huge AGENTS.md files doesn't bloat the API response.

Open questions

idquestion
Q-1Should we also try to surface what pi's --append-system-prompt would have added? Currently not visible at all; pi doesn't log CLI args to JSONL.
Q-2For claude-code sessions, this view currently uses the same heuristics. Claude Code DOES store a synthesized "session_meta" entry with tools/permissionMode; we could do better there in a follow-up.
